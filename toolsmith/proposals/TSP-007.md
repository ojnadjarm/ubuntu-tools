# TSP-007 — `pc idle` + `bench/BASELINE-IDLE.tsv` appended by `pcbench-weekly`

## Problem
There is no idle power baseline, so no efficiency proposal can show a before/after number; the only samples are ad-hoc (collector saw 4.9 W and 6.48 W package within one hour).

## Evidence
- `bench/` — `BASELINE-PCBENCH.md` only; no idle file; `pc help` has `power`, `top`, `bench` but no `idle`.
- `state/inputs.json` idle — package 4.9 W / psys 6.04 W, top waker `claude` 143 wake/s at 660 MB RSS.
- `bin/pcbench-weekly:76-78` — writes only the pcbench baseline.

## Survey
- exists: `powerstat` (RAPL, avg/stddev over N samples, Ubuntu package), https://github.com/ColinIanKing/powerstat (read 2026-09-07); `turbostat` (already used by `pc power --deep`), https://www.linux.org/docs/man8/turbostat.html (read 2026-09-07). Rejected powerstat: new apt package for what `pc power rapl` + `pc top --sort wake` already read.
- chosen: `pc idle [--seconds 60] [--json]`: median package/psys watts over the window from `pc power rapl`, top 5 wakers from `pc top --sort wake`, resident RSS of `agent@*`, `sentinel*`, `dark-eye*`; `--tsv` line appended to `bench/BASELINE-IDLE.tsv` by `pcbench-weekly` before the A/B (machine is away and quiet then).
- why: composes existing verbs; read-only; one weekly row is enough for a trend.

## Proposed change
New `bin/pc-idle`, one line in `bin/pcbench-weekly`, doc line in `KB/toolbox.md`. Test: `bin/tests/pc-idle.test.sh` with stubbed `pc power`/`pc top` output.

## Success check
- metric: rows in `bench/BASELINE-IDLE.tsv`
- before: 0 rows (`bench/BASELINE-IDLE.tsv` absent)
- target: 1 row per Sunday, psys watts with stddev
- measured by: `tail -3 bench/BASELINE-IDLE.tsv`
