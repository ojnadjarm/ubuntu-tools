# TSP-009 — `agent-*` CLIs: kill switch reads `state/pid`; name check and `-h`

## Problem
`agents-stop` finds background runs through `claude agents --json`, which does not list `agent-exec` children, while every run already writes `<name>/state/pid`; and `agent-now -h` starts a unit named `agent@-h`.

## Evidence
- `bin/agents-stop:28` — `pids=$(claude agents --json … .pid)`.
- `bin/agent-exec:47,50` — writes and removes `--pid-file`; `bin/agent-run:44` passes `$dir/state/pid`.
- `bin/agent-now:4-6`, `agent-run:5-6`, `agent-enable:5`, `agent-disable:5` — `name=$1` with only an emptiness check; no `-h`, no test that `~/agents/$name/BRIEF.md` exists.

## Survey
- exists: nothing external; local pattern in `maintenance-run:20` (`-h|--help`) and `agent-exec:27`.
- chosen: shared `agent_name_check` in `fleetlib.sh` (rejects `-*`, requires `BRIEF.md`); `agents-stop` kills `*/state/pid` first, then the old `claude agents` path as fallback.
- why: the kill switch must not depend on the agent CLI's bookkeeping (FLEET §6).

## Proposed change
`bin/fleetlib.sh`, `bin/agents-stop`, four `agent-*` scripts; `bin/tests/agents-stop.test.sh` with fake `state/pid` files pointing at a `sleep` the test started itself.

## Success check
- metric: background runs killed by `agents-stop` in the fixture
- before: 0 of 1 (pid file ignored)
- target: 1 of 1; `agent-now -h` exits 2 with usage
- measured by: `bash bin/tests/agents-stop.test.sh`
