# Runbook: rebuild this machine on new hardware (T246)

Follow the steps in order: the new box ends up as this box. Each step ends with a **verify** line, and you
move on only when it passes. Inventory source: etckeeper (`/etc/.git`) + dpkg + apt history, regenerated by
`~/agents/bin/machine-inventory` (read-only; linked into `~/.local/bin` by `install.sh`). Drift check: `machine-inventory --check` must print `gaps: 0`; a gap
means `/etc`, apt, snaps or user units changed and this file was not updated.
Last verified 2026-10-05 on Ubuntu 26.04.1 LTS, kernel 7.0.0-34-generic, ASUS Vivobook X1503ZA (BIOS X1503ZA.301).

Classes used below: **P** portable (replay as is) · **H** hardware-specific (check on the new box) ·
**S** secret (copy, never print) · **D** data (copy). The one-table summary is `KB/machine.md` "System changes".

Steps marked **owner** touch sudoers, sshd, ufw or a second access path: agents may not do them
(FLEET §5.3). The owner runs them by hand.

## 0. On the old box: export (owner, ~1 h, mostly the copy)

```bash
machine-inventory > ~/agents/backups/inventory-$(date +%F).txt            # the list this runbook replays
sudo tar -czf ~/etc-fleet.tgz -T <(machine-inventory --etc-list | grep -vE '^/etc/(passwd|group|shadow|gshadow)$')
moodle-keep                                                                  # fresh pg_dump into ~/agents/backups/moodle/{4.5,5.2}/<date>.sql.gz, restore-tested
tailscale serve status > ~/agents/backups/tailscale-serve-$(date +%F).txt
gsettings list-recursively > ~/agents/backups/gsettings-$(date +%F).txt
```
- `etc-fleet.tgz` holds S files (`/etc/agents/ntfy.env`, a Wi-Fi PSK in `/etc/netplan/90-NM-*.yaml`): keep it mode 600, move it with the home copy, delete it after step 5.
- Restic is skipped (T22 owner decision), so there is no off-machine backup: the copy in step 7 **is** the backup. Keep the old box intact until step 12 passes.
- **Verify:** `tar -tzf ~/etc-fleet.tgz | wc -l` equals `machine-inventory --etc-list | grep -cvE '/(passwd|group|shadow|gshadow)$'`; the newest dump in `~/agents/backups/moodle/5.2/` has today's date.

## 1. Base install (owner)

Ubuntu 26.04 LTS desktop, in the installer:
- the **same user name** as the old box and **uid 1000** (paths and file names below embed it: the udev ptt rule, `/etc/sudoers.d/*` (named after the user), `/etc/security/limits.d/90-agents.conf`, the AppArmor profile, user units);
- "log in automatically" on: writes `/etc/gdm3/custom.conf` (`AutomaticLoginEnable=true`, `AutomaticLogin=<user>`) — the fleet needs a live session after every boot (P);
- keyboard **latam** (`pc type` exists because `ydotool type` mistypes it), timezone Europe/Madrid, English UI;
- hostname: any name works (the old one is in `KB/machine.md` "Identity"); links use the Tailscale name (step 8).
- **Verify:** `id -u` = 1000, `loginctl show-session $(loginctl | awk '/seat0/{print $1; exit}') -p Type` = `wayland`, reboot lands on the desktop with no password.

## 2. Access (owner, by hand)

```bash
echo "$USER ALL=(ALL) NOPASSWD:ALL" | sudo tee "/etc/sudoers.d/$USER" && sudo chmod 440 "/etc/sudoers.d/$USER" && sudo visudo -c
sudo apt-get install -y openssh-server curl git etckeeper
sudo usermod -aG docker,input "$USER"         # docker group exists after step 3; re-run then
```
- etckeeper first, so every later `/etc` change lands in its history (`sudo etckeeper vcs log`).
- `/etc/ssh/sshd_config.d/50-agents.conf` (P, T25): `PasswordAuthentication no`, `PermitRootLogin no`, `MaxAuthTries 4`, `ClientAliveInterval 60`. Copy `~/.ssh/authorized_keys` (S) **before** writing it.
- **Verify:** `sudo -n true && echo ok`; `sudo sshd -t`; `ssh localhost true` with the key.
