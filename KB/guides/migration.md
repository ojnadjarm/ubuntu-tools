# Migrate this machine to new hardware: rebuild from the runbook, check drift with machine-inventory

Ticket: T246, T906 · Last verified: 2026-10-20 (T947: `machine-inventory --check` = `gaps: 0`, rc 0; `cmp` of the 3 orchestrator units in `~/agents/units` vs `~/.config/systemd/user`); before: 2026-10-19 by `machine-inventory --check` = `gaps: 56`, rc 1 (runbook drift, below) and `test -e` on every path / 2026-10-05: `gaps: 0`, negative test (stripped doc → 16 gaps, rc 1)

## When to use
Moving the fleet to a new laptop, reinstalling Ubuntu, or proving the runbook still matches this box after
someone touched `/etc`, apt, snaps or user units. Not for one service down (`KB/runbooks/<service>.md`).

## The path we took
- Exists: etckeeper (already tracking `/etc` since 2026-09-05, daily autocommit), `apt-clone` (packages only, not on this box), ansible/chezmoi (a second tracker plus a rewrite of every change as code).
- Chosen: etckeeper's git as the `/etc` source + dpkg conffile md5s + apt history, read by a small read-only bash CLI `machine-inventory`; the runbook stays prose with exact commands.
- Why: no second tracker, no new dependency, and the check catches drift the day it happens. Ansible would pay off only with several machines.

| Piece | Role |
|---|---|
| `bin/machine-inventory` | lists `/etc` changes (etckeeper diff since the baseline + the pre-etckeeper window since the installer, minus installer/package-generated and pristine package files), hand-installed apt packages, extra snaps, user units |
| `machine-inventory --check [DOC]` | every item must appear in the runbook (`/etc` paths as backticked tokens, globs allowed); exit 1 and one `GAP` line each |
| `machine-inventory --etc-list` | absolute paths, piped into `sudo tar -czf … -T -` on the old box (not `-T <(…)`: sudo closes the process-substitution fd) |
| `KB/runbooks/migration.md` | the ordered rebuild, each step with a verify line |
| `KB/machine.md` "System changes" | one-table summary (hand-maintained) |

## Exact commands
```bash
machine-inventory                       # all sections, ~9 s idle, 57 s at load ~13
machine-inventory --check               # gaps: 0 or the GAP list, rc 1
machine-inventory --etc-list | grep -vE '^/etc/(passwd|group|shadow|gshadow)$' | sudo tar -czf ~/etc-fleet.tgz -T -
```

## Pitfalls (measured)
- **Runbook drift** (2026-10-19): `--check` found 56 gaps, 37 packages (blender, clang-tidy, dotnet-sdk-10.0, gimp, krita…), 15 user
  units (pc-tmp, pulse-5h-reset…), 4 `/etc` items (`ufw/after.rules.T362.bak`, `xml/catalog`). T906 added them: `gaps: 0`, rc 0 (re-run 2026-10-20, T947). A new package, unit or `/etc` file reopens a gap: add it to `KB/runbooks/migration.md` before a move.
- Units: `claude-orchestrator.service` and `orchestrator-pulse.{service,timer}` ship in `~/agents/units` (install.sh step 4 copies them); the rest of runbook step 8's first list lives only in `~/.config/systemd/user` and arrives with the step-7 home copy.
- etckeeper's first commit is 2026-09-05 18:41, ~2.5 h after the first boot: sudoers, logind no-suspend, sleep-target masks, ydotoold, the tailscale repo, gdm autologin and a Wi-Fi profile predate it. A diff against the first commit alone missed 10 fleet files; the script adds the installer-to-baseline mtime window.
- 232 `/etc` paths changed since the baseline (renames split), most are package or snap side effects (alternatives, rc.d links, snap mounts, needrestart, alsa); the filter keeps 64 fleet items (54 from the diff + 10 from the pre-baseline window).
- Package conffiles edited in place (`netdata.conf`, `smartd.conf`) look "package-owned": compare the conffile md5 (`dpkg-query -W -f='${Conffiles}'`), do not trust `dpkg -S`.
- `KB/machine.md` is regenerated by `pc status --facts --apply`, which rewrites only its marked region and keeps "System changes" (T257).
- The package check is a word match (`git`, `tree` match anywhere): it proves mention, not that the apt line is complete.
- Battery limit: the udev rule did not hold across boots (sysfs 100 % on 2026-10-05; asus_wmi adds the node after BAT0's add event); `battery-charge-threshold.service` replaced it (T258), sysfs reads 80 on 2026-10-20 after the 10-15 boot.
