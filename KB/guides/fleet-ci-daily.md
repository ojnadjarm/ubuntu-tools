# Nightly fleet CI: the ~/agents test suite on a timer

Ticket: T459, T848, T849, T853, T861, T862, T901, T895 · Last verified: 2026-10-20 (T947: `run.sh` T895 code read, one `--skills --skip-unchanged --plan`); before: 2026-10-20 (T901: --help + code read of `fleet-ci-daily`, `ci-window`, `run.sh`, `pc-doctor` fleet_cpu); before: 2026-10-20 by `bin/tests/fleet-ci-daily.test.sh` (T553 load noise, T717 skip-unchanged days, T733 rerun scope), `ci-autofix.test.sh`, `run-sh.test.sh` (skills block T530, skip-unchanged block T717, quiet-gated tail T776) and one run of `fleet-ci-daily` under the user manager; claims re-read against code and installed units 2026-10-20 (T846)

## When to use
Reading, changing or re-running the once-a-day run of `bin/tests/run.sh -j 8` over the fleet's own tooling. A ticket still runs its own changed tests; this catches what nobody's ticket ran.

## The path we took
Copied from `ailearning-ci-daily` (T140/T402/T407): the runner owns the suite, `ci-autofix` owns the red policy unchanged.
- `bin/fleet-ci-daily`: `flock` (`state/fleet-ci.lock`, second run exits 75), `ci-window --quiet` (wait for 1-min load < 4), `run.sh -j 8`, output to `~/agents/log/fleet-ci/<date>.txt` (one file a day; a ci-autofix re-run first keeps it as `<date>.first.txt`, T733). Red files then re-run once each, serially (`run.sh -j 1 --only <file>`, output prefixed `  re-run | `) after `ci-window --quiet` capped at 900 s (T553); green ones print `load-noise: <files>` and a closing `PASS|FAIL n/m files after a serial re-run of <noise>+<red>` line (the doctor row reads the last summary), so an all-noise night exits 0. Still red ends with `ci-load: contention (…)` when the load before or after was > 6, then `✖ fleet ci red: <files red twice>` (the cause line ci-autofix keys on, so each set of failing files is its own cause).
- `units/fleet-ci-daily.{service,timer}`: daily 02:10 (after the 00:50–01:50 window), `ci-autofix --repo ~/agents … "fleet nightly" -- fleet-ci-daily`; `TimeoutStartSec=7200`, `CI_BUDGET=6900`, `CI_RUN_NEED=900` (2026-10-20 nightly: 212 files in 399 s).
- Red: one `ci-fix` attempt per cause per 24 h, one re-run (after a quiet wait on contention), `notify-owner -p high` only if still red; green after a fix resolves the `fleet nightly ci failed` need.
- Rerun scope (T733): after the fix attempt `ci-autofix` exports `CI_AUTOFIX_RERUN=<date>.first.txt`; `fleet-ci-daily` then skips the suite and runs `run.sh -j 1 --only` for the first log's `✖ fleet ci red:` files plus every test whose file, `bin/<tool>` or skill dir is newer than that log, prints `rerun scope: N red + M touched (first pass: <path>)` and `PASS|FAIL n/n files in the rerun scope`. Empty scope exits with the first pass's `run.sh rc N` (1 if none); a first log without a `✖` line runs the full suite. The cause-tried-in-24-h contention re-run stays a full suite run without the variable. `ailearning-ci-daily` ignores it (its log is still kept as `ailearning-ci.first.log`).
- `pc doctor` row `fleet-ci`: the newest log's `PASS|FAIL n/m files` line plus `; cpu <s> s (7-night median <m>)` (T862: the last 7 nights' `cpu:` lines, a night's `.first.txt` when it exists, ` on MM-DD` when the newest log has no cpu line yet); red, no summary, none, older than 48 h, or a night > 1.25× the median with ≥ 3 nights (`+N%, top <test> <s> vs <its median>`, from test-timings-history.tsv) is a WARN (never a FAIL: a red suite is not a broken machine).
- Recheck (T853): `fleet-ci-daily --recheck` re-runs the `✖ fleet ci red:` files of today's log (else the newest non-`.first` log) one at a time (`run.sh -j 1 --only <file>`, lines prefixed `  recheck | `) after `ci-window --quiet`, under the same `state/fleet-ci.lock` (75 while a run holds it), and appends `recheck HH:MM:SS: N/M green (<files>)` to that log. All green: `pc units reset-failed fleet-ci-daily.service --user --apply` + `pc need resolve "fleet nightly" --apply`; any red: rc 1; no red line (or only `run.sh rc N`): `recheck: nothing red`, rc 0.
- Busy CI units (T848): `ci-window` (both modes) is busy while a unit of `CI_UNITS` (default `fleet-ci-daily.service ailearning-ci-daily.service`, user scope) is active/activating/reloading/deactivating, except the unit whose cgroup the caller runs in (`CI_CGROUP`, default `/proc/self/cgroup`). `--quiet` waits for load < 4 AND no busy unit and names it (`…, <unit> done` / `…, but <unit> still active after N s`); plain `ci-window` exits 1 with `<unit> active`. `CI_UNITS=` (empty) turns the unit check off.
- Real-ledger guard (T861): `run.sh` exports a run-wide `CREATIVE_CI_LOG` to every file; when the real ledger (an inherited `CREATIVE_CI_LOG`, else `$HARNESS_HOME/log/creative-ci.jsonl`) gained rows or `log/creative-ci/*.json` summary copies (`scratch/` left out) during the run, it prints `run.sh: tests wrote the real creative ledger (N rows, M summary copies in …)` and the summary is FAIL even with every file ok.
- Kill switch: `agents-stop` stops the service and the timer.
- Skill tests (T530): `fleet-ci-daily` runs `run.sh -j 8 --skills`, which adds `<dir>/<skill>/tests/*.test.{sh,py,js}` from `RUN_TESTS_SKILLS` (default `~/.claude/skills:~/agents/skills`) as `skills/<skill>/...` with the same pool, timings and summary; `run.sh --only 'skills/*'` runs only them. A skill dir symlinked into both counts once and runs from the first dir. Every skill test gets a `docker` shim first on PATH (exit 125), so none reaches a real Moodle container; `SKILL_SKIP` in run.sh lists make-lesson (ailearning off limits) and `moodle-ai-setup/tests/setup.test.sh` (live half drives moodle53), printed as `skip <file> (<why>)`.
- Skip-unchanged (T717): Mon–Sat `fleet-ci-daily` passes `run.sh --skip-unchanged`; Sunday (`date +%u` = 7, `FLEET_CI_DOW` in fixtures) or `FLEET_CI_FULL=1` runs everything. A skill test whose last `state/test-timings-history.tsv` row is rc 0 with cpu_s ≥ 20 prints `SKIP unchanged <file> (green <date>, <cpu> CPU s)`, counted ok, while none of its own inputs (T849) is newer than that row: the test file; the skill entries its tokens name (scripts, followed into the scripts they name; `templates/<x>`, top-level files and dirs; fixtures by path only, `fixtures/<x>[/…]`, and `plates <name>` = `tests/fixtures/plates/<name>`, T895); the shared libs `scripts/mvlib.*` and `scripts/ci-lib.sh` plus every `../../<skill>/<path>` a scanned file names (motion-video's mvlib.sh sources gamedev's ci-lib.sh); all of `templates/` when it names new-cpp-game or cpp-ci; named `skills/<x>[/<path>]` and `agents/bin/<file>`; globs on a `# inputs: <glob> …` line in its first 10 lines; the apt key (T895): a sha16 of the `dpkg-query` versions of `bin/DEPS.tsv`'s apt packages at the skill's levels (required + test, + optional:media for motion-video, optional:gamedev for gamedev), stamped `state/skip-deps/<sha16>`, shown in `--plan` as `apt deps <sha8> since <time>`; and `RUN_TESTS_SKIP_DEPS` (default `~/opt/gamedev:<vcpkg>/versions/baseline.json`; the vcpkg tree itself is pruned, its build dirs churn). `/var/lib/dpkg/status` is no longer an input. The summary adds `, skipped N, saved ~X CPU s`. A skipped file writes no history row, so it keeps its last green date; rows age out after 30 days and Sunday refreshes them. Base 2026-10-20: 31 skill files eligible, 2,197.1 CPU s of the 3,217.8 s suite. `run.sh --skills --skip-unchanged --plan` runs nothing: per skill test `skip <file> …` or `run <file>: <blocking input> …`, then `would skip N files, <cpu> CPU s`.
- Quiet-gated serial tail (T776): files listed in `bin/tests/quiet-gated.txt` (`<path>  # <reason>`, the host-only.txt shape) leave the pool and the SERIAL lane; after both drain, `run.sh` prints `serial tail: N quiet-gated` and runs them one at a time at nice 0 with the same per-file timeout clamp and `ok|FAIL <file> <s>` lines (a timeout is still `FAIL … timeout`). Listed: mv-fog, mv-draft-speed, mv-film, mv.test, cpp-hdr, cpp-shadow. A new test that calls `quiet-gate` goes on that list. `--only <file>` runs a listed file alone as before.
- One full suite at a time (T505): a full `run.sh` (no `--only`) takes `flock` on `$XDG_RUNTIME_DIR/fleet-suite.lock` (override `RUN_TESTS_LOCK`); a second full run prints `waiting for the suite lock held by pid <n> [<agent>]` and waits, or exits 75 with `--no-wait`. `--only` runs never lock; a run nested under the holder (`FLEET_SUITE_HOLDER` set, e.g. the fixture suite in `fleet-ci-daily.test.sh`) skips it, so agent-verify CHECKs that call `run.sh` inherit the same rule.

## Exact commands
```bash
systemctl --user start fleet-ci-daily.service          # run it now through ci-autofix (a red run starts a real ci-fix agent)
fleet-ci-daily                                          # suite only, no fixer, no push
tail -3 ~/agents/log/fleet-ci/$(date +%F).txt           # today's result
pc doctor --brief | grep fleet-ci                       # the doctor row
cat ~/agents/state/ci-fix/$(date +%F).md                # red runs, fix attempt, re-run
grep "rerun scope" ~/agents/log/fleet-ci/$(date +%F).txt # what the post-fix re-run ran; first pass in <date>.first.txt
bash ~/agents/bin/tests/fleet-ci-daily.test.sh          # fixtures: green, red, contention re-run, lock, units, doctor row, skip days
FLEET_CI_FULL=1 fleet-ci-daily                          # weekday run without skip-unchanged
fleet-ci-daily --recheck                                # last log's red files alone; all green clears the failed unit + need (T853)
bash ~/agents/bin/tests/run.sh --skills --skip-unchanged --plan  # what tonight would skip and each blocker (T849)
CI_UNITS= ci-window --quiet                             # load gate only, no busy-unit check (fixture tests)
```

## Pitfalls (measured)
- Load noise (2026-10-19): at 1-min load 17.2 five wall-budget files went red (pc-io 1.12 s vs 0.8, pc-net 0.56 vs 0.4, pc-mutter, pcbench, no-person-hardcoded) and green at load 0.5; the serial re-run keeps them off ci-autofix. A green suite pays nothing extra (one quiet wait, no re-run). `run.sh` takes no file list, so the re-run is one `--only` call per file.
- A `$` in a unit's `ExecStart` must be `$$` and `%` must be `%%`: `$$(date +%%F)` reaches bash as `$(date +%F)` (probe unit, 2026-10-19).
- `systemd-run` does not expand `%h` in its command: the hand probe exited 127 in 162 ms; pass `$HOME` from the shell.
- Units are copied, not linked: after editing `~/agents/units/fleet-ci-daily.*`, `cp` them to `~/.config/systemd/user/` and `systemctl --user daemon-reload`.
- Shell tests source `. "$HOME/agents/bin/tests/lib/assert.sh"` (sets `bad=0`, `ok`/`nok`/`is`/`t`) instead of redefining them: 71 files had their own `ok()` in 6 output shapes, which broke run.sh's failure-line extraction; source it before any `bad=1` (T475, 10 files migrated, outputs byte-identical 2026-10-19).
- A fixture `run.sh` inside a test honoured an inherited `RUN_TESTS_ROOT` and ran the real suite, which ran `fleet-ci-daily.test.sh` again: recursive full suites, load 248 (2026-10-19). `run.sh` now unsets `RUN_TESTS_ROOT`/`RUN_TESTS_LOCK` after reading them; `run-sh.test.sh` fails if a nested run reaches its outer root.

- Double nightly (2026-10-20, before T733): first pass 223 files 3,433 CPU s, then ci-autofix's re-run of the whole suite 213 files 3,304 CPU s for 1 red file already re-run serially, and it overwrote the first log.

- quiet-gate inside the 8-job pool (2026-10-20 nightly, before T776): mv-fog 144.8 s wall for 34.4 CPU s at load 9.2, then a 170.0 s timeout with 0.0 CPU s at load 20.6; mv-draft-speed a 170.0 s timeout with 0.0 CPU s. The pool is never quiet, so `quiet-gate --wait` ate the whole per-file timeout; hence the serial tail.
- awk prints a bare `m + 0` with `%.6g`: an mtime max came out `1.79243e+09`, about 5,000 s off, and skip-unchanged compared against it (T717, 2026-10-20); print epochs with `printf "%.3f"`.
- T853 (2026-10-20): after `recheck 11:27:28: 1/1 green` the doctor row still read `WARN fleet-ci 2026-10-20.txt: FAIL 211/212 files` and `pc failures` still listed `ci fleet nightly`: both read the summary line, not the recheck line, and the `✖ fleet ci red:` line stays above the appended recheck (queued T897).
- T848 verifier: tests that copy the real `ci-window` and reach the real `systemctl` without `CI_UNITS=` wait on a live `ailearning-ci-daily.service` (it ran until 02:55, after fleet's 02:10 start): up to 1800 s per `--quiet` in ailearning-ci-daily.test.sh and ci-autofix.test.sh; such tests export `CI_UNITS=` (fleet-ci-daily.test.sh: T894).
- T893 (2026-10-20 11:40): `--plan` printed `would skip 0 files`: 26 of 26 eligible skill tests were blocked only by `/var/lib/dpkg/status newer than green` (any apt run touches it: 9 runs on 10-19), and `tests/fixtures/<x>` matches the bare word, so every test that says `plates` depends on all of `tests/fixtures/plates`. Fixed T895 (apt key, fixtures by path); `--plan` 2026-10-20 12:40 (T947): 0 lines blocked by dpkg, still `would skip 0 files` (blockers: `scripts/ci-lib.sh` 12, `scripts/mvlib.sh` 6, `reference/commands.md` 4, all edited today).
- T861 verifier: a real cpp-ci or mv build running beside the suite makes the run FAIL; since T904 the guard also counts `creative-ci-scratch.jsonl`, so a scratchpad game-ci/cpp-ci run beside it is a false FAIL too.
- Skip-unchanged only sees paths a skill's files name as `skills/<x>` or `agents/bin/<file>`; a tool reached by bare name on PATH is not an input, so its change waits for Sunday or `FLEET_CI_FULL=1`.
