# T05 — `pc status` health snapshot and the shared knowledge base

**Phase 0 · must · Model: opus · Estimated agent time: 90 min**

## Goal
One command tells any agent the state of the machine (text, JSON or a one-line brief), every new session starts with that brief already in context, and one folder tells any agent the facts and runbooks it needs instead of rediscovering them. Rule (PLAN §2.7): agents never ask the owner about machine state they can read themselves.

## Ground rules (every ticket)
- Read `~/.claude/CLAUDE.md` first. Never commit/push in any user repo; only `etckeeper` commits under `/etc` are allowed.
- Machine facts: `~/agents/README-pc-control.md`, `~/agents/ubuntu-ai-first/PLAN.md` (sections 3 and 4).
- Passwordless sudo and `bypassPermissions` are on. Install packages freely with apt/pipx/npm.
- Before changing anything under `/etc`: `sudo etckeeper commit "pre T<NN>"` (available after T01).
- Finish by running the Success check yourself and pasting its output in your report. Report: what works now, what is left, decisions taken.

## Context / pointers
- Existing: `~/agents/bin/boot-check.sh` (T03), `lockcheck.sh` (T02), `env.sh`. Facts scattered in the orchestrator's auto-memory (`~/.claude/projects/-home-oscar-nadjar/memory/*.md`) — read them, they are the source for `KB`.
- Tools present: docker, tailscale, upower, sensors, nmcli, ss, df, free, journalctl.
- `pc` becomes a multi-command CLI in T07; here create `~/agents/bin/pc` as a dispatcher (`pc <sub> ...` runs `~/agents/bin/pc-<sub>`) and implement only `pc status`.

## Steps
1. `~/agents/bin/pc` dispatcher + `~/agents/bin/pc-status` (bash, may use python3 for JSON). Sections: host (uptime, load, kernel), power (AC or battery, %, health, time-to-empty, power profile, lid state from `/proc/acpi/button/lid/*/state`), resources (RAM, swap, disk % for /, temps max), network (SSID, LAN IP, Tailscale IP+status, DNS, internet reachable), services (docker, tailscaled, ssh, ydotoold, cron), docker stacks (per compose project: running/expected containers, published ports), desktop (session type, lock state via lockcheck, focused window title if available, screenshot works: run `screenshot.sh` to a tmp file and check size > 10 KB), agents (tmux `claude` alive, user timers with next run, `claude agents` count). Flags: `--json`, `--check` (exit 1 if any item FAIL; thresholds: disk > 85 %, RAM avail < 2 GB, temp > 95 °C, battery < 20 % on battery, any expected container down, tailscale not Running, screenshot fail), `--brief` (one line ≤ 200 chars, < 1 s, no screenshot: e.g. `AC 100% lid=open wifi=Livebox6 ts=up docker=5/5 disk=7% load=0.3 lock=off timers=0 FAIL=none`).
1b. SessionStart hook: `~/.claude/hooks/machine-status.sh` prints hook JSON with `additionalContext` = "Machine now: <pc status --brief>. Run `pc status` for detail; never ask the owner about machine state you can read." Register it in `~/.claude/settings.json` as a second SessionStart command (keep the Moodle hook). This hook is machine-specific: do not sync it into `~/moodle-harness`; note that in the hook header.
2. Create `~/agents/KB/`: `machine.md` (generated by `pc status --facts`: hostname, IPs, ports table, env paths, users/logins for Moodle, session env vars), `quirks.md` (hand-written from the memory files: Wayland findings, killall vs pkill, docker socket, latam layout, nvm PATH), `runbooks/` with `reboot.md`, `new-wifi.md` (`nmcli dev wifi connect`), `tailscale-down.md`, `docker-down.md`, `disk-full.md` — each ≤ 15 lines with exact commands.
3. Wire it: add to `~/CLAUDE.md` under Machine: "Facts and runbooks: `~/agents/KB/` (read `machine.md` + `quirks.md` before touching the machine)". Do not edit `~/.claude/CLAUDE.md` (harness).

## Success check
```bash
pc status | head -40                     # readable sections, every line OK/FAIL/value
pc status --json | python3 -m json.tool | head -5
pc status --check; echo exit=$?         # exit=0 on the healthy machine
time pc status --brief                   # one line, real time < 1 s
claude -p --model sonnet "What is the machine's power source and lid state right now? Answer from context only, no tool calls." | tail -2   # answers from the injected brief
ls ~/agents/KB ~/agents/KB/runbooks      # machine.md quirks.md + 5 runbooks
grep -c "agents/KB" ~/CLAUDE.md          # 1
```

## Rollback
Delete `~/agents/bin/pc*`, `~/agents/KB`, `~/.claude/hooks/machine-status.sh`; remove the hook entry from `settings.json` and the line from `~/CLAUDE.md`.
